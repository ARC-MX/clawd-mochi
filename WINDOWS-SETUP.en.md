# Using Clawd Mochi from Windows

**中文版（默认）：[WINDOWS-SETUP.md](WINDOWS-SETUP.md)** — this file mirrors it. If the two
disagree, the Chinese one is what this project treats as authoritative.

For: anyone who has the device and a Windows PC. You do not need to be a developer, and you do
not need any of the tooling until Part 2.

Three parts, read only as far as you need:

- **Part 1 — Just use it**: plug in USB, join the hotspot, open the browser. No toolchain.
- **Part 2 (optional) — Build and flash from Windows**: for changing the firmware or the theme.
- **Part 3 (optional) — Let Claude Code drive it**: the pet follows Claude Code's state.

---

## Part 1 — Just use it

### 1. Plug it in (no driver needed)

Use a USB-C cable that **carries data** — some cables only carry power and the device will not
appear. This is the single most common problem.

Open **Device Manager → Ports (COM & LPT)**. You should see:

```
USB JTAG/serial debug unit (COM5)      ← the number may differ; note it down
```

Windows 10 and 11 need no driver. If nothing shows up: try another cable, try another USB port,
and look for a device with a yellow warning triangle in Device Manager.

> This board (ESP32-C3 Super Mini) puts the chip's **native USB** on that connector, not a
> CH340/CP2102 bridge — which is why there is no vendor driver to install.

### 2. Join its hotspot, open the page

The device shows its **WiFi name** and **password** on the screen (at boot, or replay it with
`logo`):

```
WiFi
ClaWD-Mochi          ← the factory default; changeable from the web page
password: clawd1234
Open browser:
192.168.4.1
```

**Trust the screen over this document** — the name may have been changed already.

Join that network from the Windows WiFi list and type the password from the screen. Windows will
say **"No Internet"** — that is expected: the device *is* the network, and nothing leaves it.

Then open **<http://192.168.4.1>** in a browser.

### 3. What the web controller does

| Section | What it is for |
| --- | --- |
| `// controls` | display on / off |
| `// brightness` | backlight level, 0–100% (stored on the device, survives a reboot) |
| `// views` | switch to the idle / done animations, the Claude Code view, or the canvas |
| `// theme` | replace the theme pack (pick a folder — it replaces what is on the device), or play a single expression |
| `// device` | change the device name (**the hotspot and the Bluetooth advertisement share it**) and the WiFi password; saving **restarts** the device, so you reconnect under the new name |
| `// terminal` | the small terminal on the device — type into it |
| Canvas | draw on the display from a phone or a touchscreen |

There is also a credit line at the very top of the page.

### 4. The serial command line, without the web page

With Python 3 installed (`pip install pyserial`, plus `pip install pillow` if you want to push
images), you can drive it over the USB cable — no hotspot needed:

```bat
python tools\mochi.py state thinking      :: play the "thinking" animation
python tools\mochi.py bright 60           :: backlight 60%
python tools\mochi.py bg "#204060"        :: the pet's background (stored in NVS)
python tools\mochi.py canvas              :: enter the drawing view
python tools\mochi.py line 20 20 220 220 "#00ff88"
python tools\mochi.py img photo.jpg       :: push a full-screen image
python tools\mochi.py ports               :: list the available serial ports
```

Over Bluetooth — no cable — use `tools\mochi_ble.py` with exactly the same words, but install
`bleak` first.

## Part 2 (optional) — Build and flash from Windows

Only needed to change the firmware or the theme.

### 1. Install ESP-IDF v6.1

Use Espressif's Windows installer (Universal Online Installer or Offline Installer) and pick
**v6.1**: this project's `sdkconfig` was generated by that version, and another one may fail on
configuration keys it does not have.

<https://dl.espressif.com/dl/esp-idf/>

The installer brings its own Python and toolchain and creates an **"ESP-IDF 6.1 PowerShell"**
(or CMD) shortcut. Run every command below in *that* terminal, not in a plain PowerShell.

### 2. Get the code

Copy this repository onto the Windows machine (`git clone` whatever address you have, or just
copy the folder).

### 3. Build and flash

In the **ESP-IDF 6.1 terminal**:

```bat
cd <repo path>\esp-idf
idf.py build
idf.py -p COM5 flash
```

Replace `COM5` with the port number from Device Manager.

- The chip target (`esp32c3`), the partition table, the web page and the theme artwork all live
  in the repository — nothing else to configure.
- **One flash writes four images**: bootloader, partition table, firmware, and the storage
  partition that holds the web page and the themes. Changing the page or a theme is therefore
  also a reflash, not a separate upload.

### 4. Watch the device log

```bat
idf.py -p COM5 monitor
```

Leave the monitor with **Ctrl + ]**. **Exit it before flashing** — the port is exclusive, and a
running monitor makes the flash fail.

## Part 3 (optional) — Let Claude Code drive it

The pet follows Claude Code: submitting a prompt plays "thinking", running a tool plays "working",
and the end of a turn plays "done".

### 1. Python dependencies

```bat
pip install pyserial bleak
```

(`bleak` is for the wireless half of the path; over USB, `pyserial` alone is enough.)

### 2. Register the hooks

Edit `%USERPROFILE%\.claude\settings.json` and add these three entries under `hooks` (adjust the
paths; **use forward slashes** so the JSON needs no escaping):

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "async": true, "timeout": 30,
        "command": "\"C:/Python311/python.exe\" \"C:/path/to/clawd-mochi/tools/mochi_hook.py\" UserPromptSubmit" } ] }
    ],
    "PreToolUse": [
      { "hooks": [ { "type": "command", "async": true, "timeout": 30,
        "command": "\"C:/Python311/python.exe\" \"C:/path/to/clawd-mochi/tools/mochi_hook.py\" PreToolUse" } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "async": true, "timeout": 30,
        "command": "\"C:/Python311/python.exe\" \"C:/path/to/clawd-mochi/tools/mochi_hook.py\" Stop" } ] }
    ]
  }
}
```

`mochi_hook.py` tries **serial first** (~0.1 s) and falls back to **Bluetooth** (~4 s) when the
cable is out. Either way it exits 0 and stays silent: a device that is off must never slow
Claude Code down.

With the cable in, serial is much the faster path; unplug the cable to have it follow you
wirelessly over Bluetooth.

### 3. Check it

```bat
python tools\mochi_hook.py PreToolUse
```

The device should switch to the "working" animation. If it does not, run the pieces by hand to
see which half fails:

```bat
python tools\mochi.py state working
python tools\mochi_ble.py state working
```

## Troubleshooting

| Symptom | What to do |
| --- | --- |
| The hotspot is not in the WiFi list | Is the device still on the boot animation (~3 s) or the WiFi info screen (10 s)? Is the screen lit at all? The name may have been changed — trust the screen |
| The browser cannot open `192.168.4.1` | Make sure you joined **the device's** hotspot, not your home WiFi; the address is `192.168.4.1`, with no port suffix |
| `idf.py flash` cannot find the port | Pass it explicitly: `idf.py -p COM5 flash`; the number is in Device Manager |
| The flash fails; the port is busy | Close `idf.py monitor`, any serial terminal, and the Arduino IDE's serial monitor |
| **The flash reports success but the device behaves as before** | ESP-IDF's incremental flash occasionally misjudges (it cost this machine an hour): delete `esp-idf\build\*_flashed.bin` and flash again; if that still fails, write `build\clawd_mochi.bin` with `esptool.py` (shipped with the installer) |
| `mochi.py` picks the wrong port | Run `python tools\mochi.py ports`. It guesses from the port's description and can be fooled (a Bluetooth virtual port, say). There is no `--port` argument yet — edit the first line of `find_port()` in `tools\mochi.py` |
| The canvas draws nothing | The page now says why (`stroke not drawn: …`). Note too that **Claude Code takes the screen back the moment it has anything to say** — that is deliberate, so the pet can always show what the agent is doing |
| Bluetooth cannot find the device | Is some other machine already connected to it? It accepts only a few centrals at once. Confirm the device is alive over serial first (`python tools\mochi.py bright`) |
